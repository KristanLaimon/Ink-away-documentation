title: "Integrate your plugin with Ink Away"
description: "Start here. You need Lua and a KOReader plugin; no Ink Away knowledge is assumed."

Ink Away adds freehand annotations to KOReader. A reader opens its drawing
editor, writes on the page, and closes it to return to reading. Ink Away handles
the drawing tools and saves the annotations.

Your plugin can subscribe to that editor's events. If you have your own page
viewer, you can also let readers annotate inside it.

## Choose an example

| Your plugin needs to… | Start here |
| --- | --- |
| React when annotation opens or closes | [Event-only consumer](/docs/integration/event-only) |
| Let users annotate a custom viewer | [Rendering consumer](/docs/integration/rendering-consumer) |

A plugin can do both. You do not need a custom viewer to subscribe to events.

## The names used in these docs

- **`ui`** is KOReader's reader UI for the open book. In your plugin, this is
  normally `self.ui`.
- **`ink`** is the ready Ink Away plugin instance. Use it to call the public methods.
- **Consumer** means your plugin object, or the object that owns its integration.
- **Viewer** is your actual KOReader widget that displays content. Only rendering
  consumers need one.
- **Surface** is a Lua table that tells Ink Away how your viewer's screen positions
  map to the book's original page coordinates.

## Connect in either loading order

Add a `configureInkAway(ink)` method to your consumer. If Ink Away is ready, call
it now. Otherwise add your consumer to its queue:

```lua
local ink = self.ui.inkAwayIntegrationAPI
if ink then
    self:configureInkAway(ink)
else
    self.ui.inkAwayPendingIntegrations = self.ui.inkAwayPendingIntegrations or {}
    self.ui.inkAwayPendingIntegrations[self] = true
end
```

Ink Away calls `self:configureInkAway(ink)` after it finishes initializing.
Both examples show what to put in that method and how to clean up afterward.
Connect again for each new reader; remove your integration when its owner closes.

## Supported version

These docs describe the fork's **`feature/plugin-integration` branch**.
Unmodified upstream 4.4.0 does not provide this API. Check
[`integration_api_version`](/docs/api/integration-api-version) before subscribing;
rendering consumers also check [`document_surface_version`](/docs/api/document-surface-version).
If Ink Away is unavailable, your plugin should continue its normal behavior.
